# ReyOS — Fixes Log

Real bugs found and fixed, with root cause. Newest first. See `bugs.md` for what's still open. Entries up to 2026-10-28 are in `fixes-old.md`.

## 2026-11-02 — Stable check: Arch Archive download timeouts reported as a failed snapshot (tools/stable-snapshot/, GitHub #26, #27)

The weekly check of Arch snapshot 2026/10/31 (run 41307235414, issue #26) failed while pacman was still downloading: `mkinitcpio`, `kded` and `libmalcontent` stalled on archive.archlinux.org ("Operation too slow. Less than 1 bytes/sec transferred the last 10 seconds"), pacman gave up on the server ("too many errors"), and the transaction was never committed. No ReyOS package or QML check ran. The workflow still opened "FAILED: keep the current date", and promote.sh treats a FAILED title as a real result, so it would never have checked 10/31 again.

- **smoke-test.sh** downloads before it installs: `pacman -Syyuuw`, then `-Suu` from the cache; `-Sw` the reyos-* packages, then `-S`. Only download steps are retried: 4 attempts, 30/60/120 s apart, and only while the errors are network ones (too slow, timed out, connection reset/refused, DNS, HTTP 5xx). A 404, a signature/checksum/corrupted-package error, unsatisfiable dependencies, file conflicts, import or QML errors fail at once, even beside a timeout. The snapshot-exists probe retries no answer, and exits 2 only on a real 404. `ParallelDownloads` 5 → 3 (archive.archlinux.org is a single server: the `*.archive.pkgbuild.com` names don't resolve). The servers are unchanged: the one snapshot date for core/extra/multilib, reyos-local from Pages and the reyos-drivers release, no live mirrors. Exit status 0 passed / 75 not validated / 1 failed / 2 bad or missing date, plus a `smoke-summary.md` (result, retries, the relevant log lines).
- **Workflow**: three issue titles: "passed: ready to promote", "FAILED: keep the current date", "NOT TESTED: download failure, not validated" (and "NOT TESTED: the check didn't finish" if the job was cancelled or timed out). A rerun of a date edits and comments on that date's open issue instead of opening a second one. Issue body = the summary; full log + summary as the `smoke-log` artifact for 90 days; summary also on the run page. 60-minute job timeout. The date input goes through `env`, no longer straight into the shell script.
- **promote.sh** reads NOT TESTED titles: never promoted, not skipped as FAILED either; when the check it started ends NOT TESTED it says so in the log and the notification.
- `tests/test_stable_snapshot_smoke.py` (14 tests, real smoke-test.sh against a fake pacman/curl/import check): full pass, the generated pacman.conf (only the snapshot), timeouts that recover, a timeout that never stops (75, 4 attempts, nothing installed), checksum on download and on install, dependency failure, 404, 404 beside a timeout, a timeout during install (75, no retry), QML failure, archive unreachable, missing snapshot, bad date. Writing them caught two bugs in the first version: the FAILED summary dropped pacman's `:: unable to satisfy dependency` line, and a missing snapshot exited 1 instead of 2 (its `exit` ran in a pipe's subshell).
- **Rerun of 2026/10/31** (run 41495216514): downloads went through, then check-imports.py failed on `import yaml`. A false positive: pc_games.py imports yaml only to read Lutris game configs, and Arch's `lutris` depends on `python-yaml`; 10/24 had it through some other package, 10/31 doesn't. `yaml` is now on-demand like `lutris` (owner's choice, instead of a control-center-gui dependency).
